# UT multiplayer games implementation plan

Goal: create two complete browser games in separate self-contained projects, in sequence, sharing Speedster's existing visual language.

Architecture: Three.js client rendering, a deterministic fixed-step host simulation, and PeerJS WebRTC data channels for private lobbies. The host accepts bounded inputs only and owns health, hits, score, checkpoints and results. Browser clients interpolate snapshots and predict their own vehicle. PeerJS Cloud performs signaling, not game-state storage. Practice bots run through the same simulation. Room errors and host departure are explicit UI states. Optional TURN/signaling configuration is documented. Each project owns its copied fonts, tokens and UI.

1. Research UT Turtle Pond and public PCL floor plans and reference images. Record real landmarks, distinguish authored gameplay changes from survey geometry.
2. Naval game first: tests for acceleration, shore collisions, swept projectile hits, teams, kills, invulnerability, respawn, match timer, victory and rematch. Implement simulation independently from rendering.
3. Build pond scene, small detailed ship models, projectile/splash/wake effects, mouse aiming, spring camera, pointer/keyboard input, sound and matching HUD.
4. Build private-lobby create/join/invite, duel/team settings, readiness, authoritative snapshots, client interpolation, scores, pause/help, reconnect/error and match results. Verify real two-browser data-channel communication.
5. Verify naval practice and multiplayer in browsers, screenshots, responsive layout and performance. Then begin kart game.
6. Kart simulation tests: steering/grip/drift, ramps/gravity, boosts, collisions, ordered checkpoints/laps, countdown/finish, positions, time-trial records. Author a PCL-informed toy-scale circuit and furniture. Reuse proven lobby/presentation modules as local copies.
7. Kart race loop with bots, private race lobbies, competitive time trials, best lap/ghost records, results and rematch. Verify real two-browser racing.
8. Review, install into two sibling project folders, publish independently if existing account access permits, and add collection links in Manta without altering Speedster. Run live checks and report concrete limits, including network traversal and artistic map changes.

Validation: node unit tests plus Playwright desktop screenshots and action tests. Multiplayer tests use real PeerJS signaling/WebRTC, distinct browser contexts and authoritative world snapshots, never fabricated remote avatars. Do not claim a global leaderboard or surveyed replica without the infrastructure or source data to support it.
